# NewLife.Video 需求文档

> 版本：v1.4 | 日期：2026-07-20

本文档描述 NewLife.Video 的愿景、核心目标和模块划分。完成状态在[功能模块清单](功能模块清单.md)中追踪，详细设计在各模块架构文档中展开。

> **外部依赖**：通过 NuGet 引用 **NewLife.Core** 和 **NewLife.Audio**。AAC 编解码及 AudioSpecificConfig 由 NewLife.Audio 提供。**NewLife.JT1078** 基于本库的 FLV 和 FMp4 基础设施实现 JT/T 1078 协议。
>
> **可选依赖**：无。所有功能均通过纯托管代码或 FFmpeg 进程管道实现，不依赖任何外部 NuGet 包。

---

## 1. 背景与愿景

### 1.1 系统定位

NewLife.Video 是一个跨平台 .NET 视频处理库，为 IoT 视频监控、通用视频处理和实时流媒体场景提供统一的 API。采用**纯托管 + FFmpeg 混合**策略：简单操作（MJPEG 编解码、YUV↔RGB 转换、容器解析、帧处理）零依赖纯托管实现；复杂编解码（H.264/H.265）委托 FFmpeg 进程。

定位为 NewLife 生态的视频基础设施，与 NewLife.Audio 形成音视频完整覆盖，复用 NewLife.Net/NewLife.Core/NewLife.IoT 生态能力。

### 1.2 愿景

- **IoT 视频全链路**：ONVIF 发现 → RTSP 拉流 → 解码 → 截图/录像/推流，一条龙搞定
- **帧级可控**：不仅是文件转码，提供逐帧解码/编码/处理能力
- **纯托管优先**：能不用 FFmpeg 就不用，降低部署复杂度
- **中文生态**：文档、注释、错误信息简体中文，降低国内开发者门槛

## 2. CODEC 视频编解码引擎

视频数据在编码格式和原始帧之间的双向转换，是整个库的核心。

- **CODEC-1 视频编码类型枚举**：定义 `VideoTypes`，覆盖 H.264/H.265/MJPEG/VP8/VP9/AV1 以及原始像素格式 YUV420P/NV12/RGB24/BGR24 等
- **CODEC-2 编解码器统一接口**：`IVideoCodec` 定义 `Decode(VPacket) → VideoFrame[]` / `Encode(VideoFrame[]) → VPacket`，`ICodecInfo` 提供元数据
- **CODEC-3 编解码工厂与注册表**：`VideoCodecFactory`（编解码入口）+ `CodecRegistry`（编解码器注册/查找），支持无状态单例和有状态工厂两种注册模式
- **CODEC-4 纯托管 MJPEG 编解码器**：基线 JPEG DCT Huffman 编解码，零外部依赖，支持 YUV420P/422P 色彩子采样
- **CODEC-5 纯托管 YUV↔RGB 颜色空间转换**：YUV420P/NV12/NV21 ↔ RGB24/BGR24/BGRA32 双向转换，SIMD 加速
- **CODEC-6 FFmpeg 进程封装层**：`FFmpegInvoker` 统一管理 ffmpeg/ffprobe 进程调用、管道通信、参数构建、进度解析
- **CODEC-7 FFmpeg H.264 解码器**：通过管道接收 H.264 裸流，输出 YUV420P 原始帧
- **CODEC-8 FFmpeg H.264 编码器**：通过管道接收 YUV420P 原始帧，输出 H.264 裸流
- **CODEC-9 FFmpeg H.265 解码器**：通过管道接收 H.265 裸流，输出 YUV420P 原始帧
- **CODEC-10 FFmpeg H.265 编码器**：通过管道接收 YUV420P 原始帧，输出 H.265 裸流
- **CODEC-11 芯片视频头适配**：`IVideoChipHeader` 接口 + 海思/大华/宇视实现，与 NewLife.Audio 的芯片头模式一致
- **CODEC-12 编码格式自动检测**：根据数据流特征自动识别视频编码类型（H.264 起始码/NAL、H.265 VPS/SPS/PPS、JPEG SOI 标记等）
- **CODEC-13 FFmpeg AV1 解码器**：通过管道接收 AV1 裸流，输出 YUV420P 原始帧，复用 FFmpegInvoker 管道模式
- **CODEC-14 FFmpeg AV1 编码器**：通过管道接收 YUV420P 原始帧，输出 AV1 裸流，使用 libaom-av1/libsvtav1 软件编码
- **CODEC-15 H.264 编码解析辅助**：纯 H.264 SPS 参数集解析（ExpGolombReader，ref struct 零分配）+ NAL Unit 头解析（NALUHeader），纯托管实现
- **CODEC-16 硬件编码器参数透传**：FFmpeg 编码器支持用户指定编码器类型（libx264/h264_nvenc/h264_qsv 等）和编码参数（预设/码率/GOP/配置项），通过 FFmpegArgs 构建器透传给 FFmpeg 进程。低投入高收益，使 GPU 硬件加速编解码成为可能，无需独立实现 NVENC/QSV 模块

## 3. CONT 视频容器格式

视频文件的读写、封装与解封装，从容器中提取编码数据流。

### 基础设施层

- **CONT-16 FLV 容器格式基础设施**：纯 FLV 格式原语，位于 `Flv/` 目录，配合 NewLife.Audio 支持 JT1078 标准
  - FLV 枚举体系：`TagType`（Audio/Video/Script）、`CodecId`（AVC/HEVC/VP6 等）、`AudioFormat`（AAC/MP3/G711 等）、`FrameType`（关键帧/非关键帧）、`AVCPacketType`/`AACPacketType`、`SampleBit`/`ChannelType`
  - AMF3 元数据系统：`Amf3` + `IAmf3Metadata` + 12 种元数据类型（时长/帧率/码率/分辨率/编解码器等），支持视频+音频的 `onMetaData` Script Tag
  - FLV 数据结构：`FlvHeader`（readonly struct，9 字节头）、`FlvTags`（Tag 数据模型）、`VideoTags`/`AudioTags`/`AvcVideoPacke`/`AacPacke`（音视频标签载荷）
  - 编解码器配置：`AVCDecoderConfigurationRecord`（avcC，ISO 14496-15）、`AudioSpecificConfig`（AAC，ISO 14496-3，由 NewLife.Audio 提供）
  - 底层写入器：`FlvBufferWriter`（ref partial struct，基于 Span<byte> 零分配大端写入）+ `FlvMessagePackWriter`（AMF0/AMF3/FLV Tag 序列化）
  - 内存池：`FlvArrayPool`（ArrayPool 辅助）

- **CONT-17 ISO BMFF Box 模型基础设施**：纯 ISO BMFF 格式原语，位于 `FMp4/` 目录
  - Box 层级：`Mp4Box`（抽象基类，Size + BoxType + Start/End）→ `FullBox`（+ Version + Flags）
  - 49+ 标准 Box 类型：`FileTypeBox`（ftyp）、`MovieBox`（moov）、`MovieHeaderBox`（mvhd）、`TrackBox`（trak）、`TrackHeaderBox`（tkhd）、`MediaBox`（mdia）、`MediaHeaderBox`（mdhd）、`HandlerBox`（hdlr）、`MediaInformationBox`（minf）、`VideoMediaHeaderBox`（vmhd）、`SoundMediaHeaderBox`（smhd）、`SampleTableBox`（stbl）、`SampleDescriptionBox`（stsd）、`SampleSizeBox`（stsz）、`SampleToChunkBox`（stsc）、`ChunkOffsetBox`（stco/co64）、`SyncSampleBox`（stss）、`TimeToSampleBox`（stts）、`CompositionOffsetBox`（ctts）等
  - 片段 Box：`MovieFragmentBox`（moof）、`MovieFragmentHeaderBox`（mfhd）、`TrackFragmentBox`（traf）、`TrackFragmentHeaderBox`（tfhd）、`TrackRunBox`（trun）、`TrackFragmentBaseMediaDecodeTimeBox`（tfdt）
  - 流式/DASH Box：`SegmentTypeBox`（styp）、`SegmentIndexBox`（sidx）、`SubsegmentIndexBox`（ssix）、`MovieFragmentRandomAccessBox`（mfra/tfra/mfro）
  - 配置 Box：`AVCConfigurationBox`（avcC）+ `AVCDecoderConfigurationRecord`（ISO 14496-15）
  - SampleEntry 层级：`SampleEntry` → `VisualSampleEntry`/`AudioSampleEntry` → `AVC1SampleEntry`
  - 底层写入器：`FMp4BufferWriter`（ref partial struct）+ `FMp4MessagePackWriter`/`FMp4MessagePackReader` + `IFMp4MessagePackFormatter` 序列化接口

### 读写器实现

- **CONT-1 容器读取器接口**：`IVideoContainerReader` 定义 `ReadFrame()` / `SeekFrame()`，暴露 VideoCodecType/TotalFrames/Duration/VideoWidth/VideoHeight
- **CONT-2 容器写入器接口**：`IVideoContainerWriter` 定义 `WriteMetadata()` / `WriteFrame()` / `Flush()`
- **CONT-3 容器工厂**：`VideoContainerFactory` 按扩展名 + 魔术字节路由，自动选择读取器/写入器
- **CONT-4 纯托管 MP4 读取器**：解析 ftyp/moov/mdat/avcC/hvcC 盒结构，提取 H.264/H.265 裸流和元数据
- **CONT-5 纯托管 FLV 读取器**：解析 FLV Header + VideoTag/AudioTag/ScriptTag 结构，提取 H.264/H.265/AAC 裸流
- **CONT-6 纯托管 AVI 读取器**：基于 RIFF 容器扩展，解析 strh/strf 流头，提取视频帧
- **CONT-7 纯托管 TS 读取器骨架**：解析 PAT/PMT/PES 结构，提取 H.264/H.265 流
- **CONT-8 纯托管 MKV/WebM 读取器骨架**：EBML 基础解析，提取视频轨数据
- **CONT-9 原始视频帧读写**：`RawVideoReader` / `RawVideoWriter` 支持 YUV420P/NV12/RGB24 等原始像素格式的逐帧读写
- **CONT-10 纯托管 MP4 写入器**：生成 ftyp/moov/mdat 盒结构，支持 avcC/hvcC 配置盒写入。已复用 CONT-17 ISO BMFF Box 模型重构
- **CONT-11 纯托管 FLV 写入器**：生成 FLV Header + VideoTag + AudioTag + ScriptTag 结构，自动写入 AVCDecoderConfigurationRecord 序列头。支持 AAC 音频帧写入（需 NewLife.Audio 的 AAC 编码器和 AudioSpecificConfig）+ AMF3 onMetaData 元数据 Script Tag
- **CONT-12 纯托管 AVI 写入器**：基于 RIFF 容器扩展，生成 avih/strh/strf 流头 + movi 数据块 + idx1 索引
- **CONT-13 纯托管 MKV/WebM 写入器**：EBML 头 + Segment/Info/Tracks/Cluster 结构，支持 SimpleBlock 写入
- **CONT-14 纯托管 TS 写入器**：生成 PAT/PMT/PES 结构，支持 188 字节 TS 包封装，HLS 分段底层依赖
- **CONT-15 纯托管 fMP4/CMAF 分段写入器**：基于 CONT-17 ISO BMFF Box 模型，生成 ftyp+moov+循环(moof+mdat)的分段 MP4 结构，支持 DASH sidx/ssix 盒，适用于直播录制和 CMAF 兼容流

## 4. PROC 视频处理与转换

视频帧的变换、增强和效果处理。

- **PROC-1 视频处理器统一接口**：`IVideoProcessor` 定义 `ProcessFrame(VideoFrame) → VideoFrame`，拉模型
- **PROC-2 帧缩放**：最近邻/双线性/双三次插值，支持保持宽高比和填充模式
- **PROC-3 帧裁剪**：按像素区域裁剪，支持负坐标和越界自动裁剪
- **PROC-4 帧旋转与翻转**：90°/180°/270° 旋转，水平/垂直镜像
- **PROC-5 色彩空间转换**：依赖 CODEC-5 的 YUV↔RGB 转换，作为处理器封装供管线使用
- **PROC-6 帧率转换**：抽帧（降帧率）和帧复制/插值（升帧率）
- **PROC-7 色彩调整**：亮度、对比度、饱和度、色调调整
- **PROC-8 水印叠加**：文字/图像水印，支持位置、透明度、缩放
- **PROC-9 视频处理管线**：`VideoPipeline` 支持链式组合多个处理器，内部自动管理格式转换
- **PROC-10 FFmpeg 滤镜链集成**：将 FFmpeg libavfilter 滤镜能力封装为 `IVideoProcessor`，支持去噪/锐化/去隔行/缩放等滤镜，与纯托管 VideoPipeline 可互换

## 5. IMG 图像帧处理

从视频流中提取静态图像，或从图像序列生成视频。

- **IMG-1 帧快照提取**：从视频流/文件按时间或帧号提取快照，输出为常用图像格式
- **IMG-2 关键帧缩略图**：提取所有关键帧，拼接为预览缩略图
- **IMG-3 帧序列生成视频**：将 `IEnumerable<VideoFrame>` 或图像文件序列编码为视频
- **IMG-4 运动检测**：帧差法 + 自适应阈值 + 连通域分析，输出运动区域矩形
- **IMG-5 时间戳叠加**：在帧上叠加 OSD 时间戳文本，支持自定义字体大小/颜色/位置
- **IMG-6 多格式快照输出**：帧快照支持输出为 JPEG/BMP/TIFF/PNG/WebP/GIF/AVIF 七格式。JPEG/BMP/TIFF/PNG/WebP/GIF 纯托管编码，AVIF 通过 FFmpeg 管道编码
- **IMG-7 纯托管 PNG 编码器**：纯托管实现 VideoFrame→PNG 编码，利用 .NET 内置 DeflateStream 压缩 + CRC32 校验 + Paeth 滤波。替代原 ImageSharp 方案的 PNG 编码能力
- **IMG-8 纯托管 GIF 编码器**：纯托管实现 VideoFrame→GIF 编码（GIF 87a/89a），自研 LZW 压缩实现，支持自适应调色板。替代原 SkiaSharp 方案的 GIF 编码能力
- **IMG-9 批量帧图像编码管线**：将帧序列（`IEnumerable<VideoFrame>`）批量编码为多格式图像序列或动画 GIF/WebP/TIFF。支持配置输出格式、质量控制参数、帧范围选择，适用于缩略图墙、视频预览图生成等场景
- **IMG-10 纯托管 WebP 无损编码器**：纯托管实现 VideoFrame→WebP 无损编码（VP8L 格式），使用 RIFF 容器封装。替代 FFmpeg 管道的 WebP 编码路径
- **IMG-11 纯托管动画 GIF 编码器**：在 IMG-8 基础上扩展多帧支持，将帧序列编码为动画 GIF（GIF 89a），支持帧间隔、循环次数、全局/局部调色板

## 6. DEV 视频设备 I/O

摄像头采集和屏幕捕获的抽象。

- **DEV-1 视频捕获设备接口**：`IVideoCaptureDevice` 定义设备名/支持格式/StartCapture/StopCapture/FrameCaptured 事件
- **DEV-2 设备管理**：`VideoDeviceManager` 枚举视频设备，获取支持的分辨率和帧率
- **DEV-3 后端工厂**：`VideoBackendFactory` 根据平台自动选择后端
- **DEV-4 Windows DirectShow 后端**：通过 DirectShow 采集摄像头视频
- **DEV-5 Linux V4L2 后端**：通过 V4L2 接口采集摄像头视频
- **DEV-6 屏幕捕获**：Windows DXGI 桌面捕获 / 跨平台兼容方案
- **DEV-7 macOS AVFoundation 后端骨架**：AVFoundation 摄像头采集接口定义与骨架实现，为后续 macOS 完整支持预留扩展点

## 7. STRM 视频流媒体

视频流的网络传输协议支持。

- **STRM-1 RTSP 客户端**：RTSP 拉流（OPTIONS→DESCRIBE→SETUP→PLAY→RTP→TEARDOWN），基于 NewLife.Net
- **STRM-2 RTP H.264 封包/解包**：RFC 6184 实现，单 NAL/FU-A/STAP-A 封包模式
- **STRM-3 RTP H.265 封包/解包**：RFC 7798 实现
- **STRM-4 RTMP 推流客户端**：RTMP 握手 + FLV 音视频流推送，基于 NewLife.Net
- **STRM-5 HLS 分段器**：m3u8 播放列表生成 + TS 分段文件生成
- **STRM-6 WebSocket 视频通道**：基于 NewLife.Net 的 WebSocket 双向视频帧传输
- **STRM-7 抖动缓冲**：`JitterBuffer` 可配置延迟的接收缓冲，平滑网络抖动

## 8. IOT IoT 视频适配

面向物联网视频监控场景的专用协议和适配。

- **IOT-1 ONVIF 设备发现**：WS-Discovery 协议 (UDP 组播)，发现局域网内 ONVIF 摄像头
- **IOT-2 ONVIF 媒体服务与边缘存储**：GetProfiles/GetStreamUri/GetSnapshotUri + 基于 OnvifRecordingClient 的 Profile G 边缘存储操作（GetRecordings/CreateRecording/DeleteRecording/GetRecordingOptions）
- **IOT-3 ONVIF PTZ 控制**：云台旋转/变焦/预置位操作
- **IOT-4 GB/T 28181 设备注册**：SIP 注册与心跳，基于 NewLife.Net
- **IOT-5 GB/T 28181 实时点播**：SIP INVITE 拉流 + RTP 接收
- **IOT-6 录像计划管理**：定时录像 + 事件触发录像 + 录像文件管理
- **IOT-7 IoT 芯片视频头适配**：海思/大华/宇视视频帧头，与 CODEC-11 芯片头接口配合

## 9. TRANS 高级转码与编排

上层编排 API，简化常见视频处理任务的调用流程。

- **TRANS-1 FFmpeg 运行时自动下载**：提供 `FFmpegSetup` 工具类，自动检测系统 FFmpeg 安装，在缺失时可从指定镜像源自动下载 FFmpeg 二进制（参考 FFMpegCore 的设计）。支持自定义下载源、版本选择和缓存策略，降低用户入门门槛
- **TRANS-2 转码高级 API**：提供 `VideoTranscoder` 高级转码类，一行代码完成常见转码场景（格式转换/分辨率缩放/编码器切换/码率控制）。内部编排容器读取→解码→帧处理→编码→容器写入管线，支持进度回调

---

## 10. PLAY 视频流式播放

视频流的播放层支持，弥补当前仅有流协议库（RTSP/RTMP/HLS/RTP）而无播放器组件的缺口。

- **PLAY-1 基于 FFmpeg 的轻量播放引擎 FfmpegPlayer**：`FfmpegPlayer` 类利用 FFmpegInvoker 管道输出 rawvideo，支持 RTSP/RTMP/HLS/本地文件等协议的一键播放。提供 `IPlayerControl` 接口抽象（Play/Pause/Stop/Seek/FrameDecoded 事件），延迟可控。基于进程管道的纯托管播放方案，无需 VLC/LibVLC 依赖
- **PLAY-2 fMP4 over WebSocket 实时播放**：基于 CONT-15 fMP4 分段写入器 + STRM-6 WebSocket 视频通道，实现服务端实时分段 fMP4 推送 + 浏览器 Media Source Extensions 播放。延迟 1-3 秒，适用于摄像头实时预览
- **PLAY-3 RTSP→WebSocket 桥接服务**：提供 `RtspToWebSocketBridge` 服务组件，接收 RTSP 摄像头流，解 RTP → 转封装为 fMP4 分段 → 通过 WebSocket 推送给浏览器播放。解决 RTSP 无法在浏览器直接播放的问题
- **PLAY-4 多路摄像头实时预览管理**：提供 `CameraStreamManager` 多路摄像头流管理器，统一管理多个摄像头的 RTSP 连接、自动重连、连接池复用、流健康监测。单进程支持 16+ 路 1080p 摄像头并发
- **PLAY-5 纯托管帧渲染器**：提供 `VideoFrameRenderer` 将 VideoFrame 渲染到目标表面。支持 Windows `WriteableBitmap`（WPF/WinForms）和跨平台内存缓冲区输出。配合 PLAY-1 FfmpegPlayer 的 `FrameDecoded` 事件，实现纯托管帧渲染管线，替代原 SkiaSharp 渲染方案

## 11. 🧊 暂缓清单

计划做但现在不做，注明显式理由和可重新评估的前提。

| 功能 | 暂缓理由 | 解冻前提 |
|---|---|---|
| GPU 硬件编解码 (NVENC/QSV/AMF) | 需要各厂商 SDK，跨平台复杂度高 | CODEC-16 参数透传可先覆盖基本需求；后续调研 P/Invoke 直接调用可行性 |
| WebRTC 完整信令栈 | 信令与业务高度耦合，不适合通用库 | 社区需求反馈，评估作为独立 NuGet 包 |
| VP8/VP9 纯托管编解码 | 算法复杂，暂无 .NET 实现参考 | .NET 社区出现可用实现后评估集成 |
| AV1 解码器 | 纯托管性能不足，FFmpeg 可覆盖 | FFMpeg 封装稳定后集成 |
| AV1 编码器 | 编码复杂度极高，需求尚少 | 市场需求明确后评估 |
| 视频编辑时间线 | 属于上层应用，不适合基础库 | 独立应用层项目 |
| AI/ML 视频分析 | 目标检测/人脸识别等属于上层应用 | 独立 AI 模块或集成第三方 |
| macOS AVFoundation 后端 | 开发资源有限，优先 Win+Linux | macOS 用户需求反馈 |
| RTSP 服务端 | 当前需求以客户端拉流为主 | IoT 设备端推流需求出现后，与 PLAY-4 多路摄像头管理配合 |

---

## 12. 不做什么

明确排除的功能项，避免后续争议。

- **ASR/TTS 语音识别合成**：属于语音领域，由 NewLife.Audio 或其他语音库负责
- **MIDI 音乐处理**：属于音频领域
- **3D 渲染/游戏引擎**：不在视频处理范畴
- **DRM/加密视频**：版权保护实现各异，不适合通用库
- **云服务 SDK**：阿里云/腾讯云等视频服务 SDK，属于独立产品接入
- **视频播放器 UI 控件**：基础库不包含 UI 层。播放能力通过 PLAY 模块的 FfmpegPlayer + VideoFrameRenderer API 封装提供，UI 控件由上层应用集成
