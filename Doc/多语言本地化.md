# 多语言本地化

> 基线：NewLife.Core 12 编译期词表｜运行时 11 种语言｜英文为源文与兜底

## 1. 语言分层

本库按 NuGet 下载量分层维护运行时词表：下载量较高的核心组件对齐 NewLife.Core 的 31 种语言，其余组件维护 11 种语言（与 README 读者一致）。缺失译文在运行时自动回退英文，新增语言不需要改代码。

词表文件（10 个，另有英文源文兜底）：

- zh-Hans
- zh-Hant
- es
- de
- ja
- fr
- pt
- ru
- ko
- ar

## 2. 词表文件

- `NewLife.Video/Locales`

- 文件名即 BCP 47 语言代码；英文是源文与兜底，**不需要** `en.yml`。
- 键为**英文原文**，必须与代码字符串逐字一致（含空格与标点）；占位符 `{0}` 与格式说明符 `{1:n0}` 必须与英文一致。
- 词表由 NewLife.Core 包内的源生成器在编译期读取并生成压缩语言表，NativeAOT 下同样可用。

## 3. 新增一条消息

1. 代码中写英文源文：异常用 `L.T("Session {0} is closed.", sessionId)`，日志直接写英文模板。
2. 带前缀的日志统一走 `VideoLog.Info/Write`，内部调用 NewLife.Core 的 `WritePrefixed`，先翻译再拼接前缀；不要把前缀写进模板，否则整串查表永远回退英文。
3. 在全部语言文件的同一位置补齐该键；遗漏只回退英文，不会编译失败。
4. 运行校验脚本确认键集合、占位符与格式说明符一致。

## 4. 校验

```powershell
# 词表门禁：键集合、占位符、格式说明符、孤儿键、L.T 缺词条
pwsh -File Tools/Scripts/check-locales.ps1

# 人工观察：列出各语言译文，并标出与英文原文相同的未翻译条目
pwsh -File Tools/Scripts/show-locales.ps1 -All

# 只校验词表内部一致性
pwsh -File Tools/Scripts/check-locales.ps1 -SkipOrphan
```

CI 的 localization job 会执行同一脚本。

## 5. 程序集与 NuGet 元数据

- `AssemblyTitle`/`Description` 使用英文源文，并把这**同一个字符串**作为 key 写入全部 10 份词表；中文给译文，其它语言同样给译文（本仓要求所有 key 全语言翻译）。
- `PackageDescription` 保留中英混排，`Description` 保持纯英文供反射使用；NuGet 元数据不随界面语言变化。
- 展示层（关于页、服务注册等）反射读取标题/描述后调用 `L.T(value)` 得到当前语言文本。
- `check-locales.ps1` 的源文扫描包含 `.cs` 与 `.csproj`，程序集元数据 key 不会被判为孤儿键。

## 6. 测试

`XUnitTest/LocalizationTests.cs` 遍历 10 种语言，验证普通消息、异常消息、带前缀日志、程序集标题与描述。

```powershell
dotnet test XUnitTest/XUnitTest.csproj -c Release --filter "FullyQualifiedName~LocalizationTests"
```

> `File not found.` 等少数 key 与 NewLife.Core 内置词表重名，类库默认不覆盖 Core 译文；测试与验收以 Core 的实际输出为准。
